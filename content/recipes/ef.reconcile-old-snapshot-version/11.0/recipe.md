# Reconcile a snapshot made by an older EF version

## Goal

Check an older EF model snapshot after upgrading, distinguish a real schema change, and regenerate only deliberately reviewed migration artifacts.

## Older approach

EF10 generates the original Avocet snapshot and migration. Review model differences and scaffold actual schema changes before applying them.

## Newer approach

EF11 reports an older snapshot when pending differences exist. Inspect the model and generated operations: the same warning can accompany a genuine schema change.

{{snippet:n11-samples-net11-0-avocetsnapshot-avocetsnapshot-csproj}}

## Migration

1. Preserve the existing migration history and snapshot before upgrading. The older Avocet snapshot is generated by real EF10 tooling, not an edited ProductVersion annotation.
2. Restore/build under the current SDK and run migrations has-pending-model-changes. The unchanged Ring model matches its EF10 snapshot in the measured EF11 graph.
3. Run database update. When differences exist and the snapshot is old, EF11 emits OldMigrationVersionWarning. This warning identifies a possible snapshot-generation cause; it does not prove there is no genuine schema change. The shadow Count control is a genuine difference and triggers the same warning.
4. With an unchanged model, scaffold RefreshSnapshot. Inspect both Up and Down and the regenerated snapshot. The measured migration has empty operations and a current ProductVersion. Review generated operations before applying; do not erase nonempty operations to force this result.
5. Apply the reviewed migration and validate again. With a current snapshot, the Count control produces PendingModelChangesWarning and fails update until a real migration is scaffolded. Keep that protection enabled; never suppress every pending-model warning.
6. For a genuine change, scaffold a separate migration, inspect its schema operations and apply it to an isolated database before deployment. Existing EF10 generation and explicit migration review remain valid. Branch-divergence/latest-ID reconciliation belongs to a separate recipe.

## Constraints

Original Windows x64 comparisons: SDK10.0.403/C#14/EF10.0.13 versus SDK11.0.100/C#15. EF11 tooling uses RC2; Cosmos uses RC3. EF11 requires net11.0; this is not an older-runtime EF11 route or GA proof. No language-preview opt-in. Console/database guidance has no rendering mode. Keep exact locks; restore requires network access. The installed guidance is offline. No additional .NET10 foundation or recurring platform matrix is introduced.

SQLite uses the actual bundled native Windows x64 engines. Matching EF/Design/dotnet-ef and patched Pkcs10.0.13 are tooling dependencies. Other platforms, encrypted engines, PMC and NativeAOT are not established.
