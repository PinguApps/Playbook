# Web and data authoring inventory

Research date: 16 October 2026. Planning only; no samples, SDK installation, compilation, browser execution, database execution, or package verification. Proposed IDs and grouping are reviewable inventory entries, not published contracts. All goal labels below were written for Playbook; the guide's demonstrations and code were not copied.

This audit covers every top-level change in the current cumulative ASP.NET Core 11 and EF Core 11 articles, their migration/breaking-change inventories, and the canonical RC1/RC2 component notes. It preserves the accepted 25 guide topics, seven additions and three expansions explicitly. It is not an exhaustive API-diff audit. GA reconciliation remains mandatory. A source-review inclusion does not satisfy the example compilation gate.

Inventory size: 156 disposition rows — 127 included goal proposals, 18 grouped source items, 10 excluded items/groups, and one unresolved candidate. These are planning counts, not a promised final recipe count. All 25 guide entries and all three expansions have explicit rows; the seven additions occupy ten rows because the AI addition is split into four proposed goals.

## Source register and reading rules

- [W] is the cumulative ASP.NET Core article. Its source composes individual [official include files][WI]; the feature names in the tables identify the relevant include/section.
- [WM] is the upgrade guide; [WB] is the complete linked ASP.NET Core breaking-change table. Each WB row names its corresponding article slug where useful.
- [W1], [W4], [W5], [W6], [W7], [WR1], [WR2] are canonical release snapshots, used when the cumulative page omits a required baseline topic or retains stale preview details.
- [E] and [EB] are cumulative EF new-feature and breaking-change articles. Their section anchors and provider requirements are part of the source evidence. [ER1]/[ER2] describe stabilization fixes, not an additional feature catalogue.
- `included` means a proposed authored goal qualifies. `grouped` means its source item is covered under the named goal, with no separate recipe. `excluded` means the documented change needs no different authored approach. `unresolved` means a factual release/availability issue blocks a reliable final recipe; it does not reject experimental APIs.
- Unless stated otherwise, web entries describe ASP.NET Core 11 with the .NET 11 SDK/runtime and matching framework/package assets. EF Core 11 requires .NET 11 SDK/runtime and EF Core 11/provider packages. These are consumer prerequisites, separate from Playbook's host. Browser, hosting, database and client restrictions below are additional dimensions; none is detected by the server.
- The previous comparison is .NET 10. Preview-to-RC corrections are authoring instructions for preparing the final recipe, not additional previous-release editions. Conditional older-target package routes require their own verified assets before inclusion.

## Authoring choices and evidence gaps

- Retain four AI recipes: conversation streaming, tool rendering, approval and synchronized state solve distinct goals. Link them into a sequence where useful; do not collapse their independent discovery identities.
- Keep migrations individual when they address distinct source, data or security outcomes. Link migrations that must be sequenced; group only changes serving the same goal. This follows the accepted goal-based recipe unit rather than reopening coverage.
- Choose original fictional business domains and representative SQL Server/Cosmos examples during authoring. These are implementation choices, not further product approvals. Available isolated database resources and exact provider-feature support remain verification prerequisites; no provisioning or database mutation is authorized by this inventory.
- No further product-boundary decision is identified in this owned inventory. The unresolved entries below concern source availability, final contracts or implementation evidence.
- DBSC is an availability question to resolve from GA artifacts, not a question for Pingu to answer from memory. Likewise, reconcile final JSON/vector index feature status and all exact provider/client versions before marking examples verified.
- Confirm the generated worker timeout/cancellation contract, browser-hosted-service shutdown, browser-options sharing report, RenderFragment restrictions, QuickGrid status and declaration signatures against installed artifacts during implementation. No current entry claims those checks ran.
- The cumulative Blazor source omits some required baseline items; explicit G04/G11 mappings use canonical earlier release notes so they cannot disappear in a cumulative-only pass.
- MVC/Razor Pages/gRPC/Hybrid were reviewed through the listed families. No distinct gRPC or Hybrid goal was invented. A subsequent public API diff may add qualifying goals; this register does not claim every public API was audited.
- No launch content should use RC-only removed APIs merely because an older official page still shows them. GA-focused editions must incorporate the conflict resolutions above and explicitly retain genuinely experimental APIs that still exist.
