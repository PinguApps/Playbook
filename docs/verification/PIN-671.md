# PIN-671 verification

Recorded 18 October 2026. This verifies the content packaging gate and the existing property recipe, not release-wide readiness.

## Acceptance coverage

1. **Metadata and canonical references:** build generation checks stable ID/path/edition identity, duplicates, introduction compatibility, declared .NET 10/11 targets, explicit prerequisite routes, route source/exact-target evidence references, HTTPS provenance, sample SDK/language/target baselines, experimental opt-ins/limitations, canonical sample membership and snippet markers. A single temporary fixture based on the property recipe exercises eleven meaningful corruptions. The pre-fix validator accepted `csharp..invalid`; the new fixture rejects it. This is structural validation, not proof that a referenced page is reachable or an arbitrary API is stable.
2. **One offline content pipeline:** discovery and detail use the same generated embedded edition. The installed scenarios compare their title, goal and complete applicability; both JSON representations must match. Served older/newer snippets must exactly match independently embedded canonical sample regions. Empty/missing narrative sections, copied fenced implementations, missing newer snippets and migration sections containing only a reference link are rejected. Human review still checks semantic completeness, originality, official-source accuracy and dependency versions.
3. **Actual packaging boundary:** `pack --no-build` rejects incomplete Markdown and otherwise-valid metadata changed after compilation. The fixture first confirms its unchanged copy matches the compiled catalogue, then changes the goal; both negative pack calls fail without producing a package. The positive artifact is packed once and tested as an installed stdio server on Windows and without network/checkout access on Linux. No catalogue service or extra production project was added.

`applicability.routes` follows the format already proposed by PIN-669 / PR #4. `optIns` and `stabilityLimitations` are additional explicit route disclosures, defaulted to empty arrays for stable recipes. The served property edition remains stable with the same ID, title, goal, examples and requirements. This development contract changes the old flat applicability shape; merge coordination is needed with PR #4 because both touch schema, metadata and tests. PIN-669's aliases, release resolution, coverage disclosures and errors were not copied into this change.

## Inspect what an agent receives

Tested using the real built stdio server and pinned MCP Inspector 2.11.0. Requires Node 22.19 or later; Inspector's first installation is an online preparation step. See the [full Inspector walkthrough](../inspect-guidance.md).

```powershell
Set-Location V:\_worktrees\Playbook\t3-7406bc2b
dotnet build ./src/PinguApps.Playbook -c Release
$server = (Resolve-Path ./src/PinguApps.Playbook/bin/Release/net10.0/PinguApps.Playbook.dll).Path
$inspector = @('--yes', '@modelcontextprotocol/inspector@2.11.0', '--cli', '--format', 'json', '--quiet')
$catalogue = npx @inspector --method tools/call --tool-name list_recipes --tool-arg 'targetVersion="10.0"' -- dotnet $server mcp | ConvertFrom-Json
$catalogue.result.structuredContent.recipes | Format-List id, title, goal
$response = npx @inspector --method tools/call --tool-name get_recipe --tool-arg id=csharp.validate-property-assignment --tool-arg 'targetVersion="10.0"' -- dotnet $server mcp | ConvertFrom-Json
$recipe = $response.result.structuredContent.recipe
$recipe.markdown | Show-Markdown
$recipe.applicability.routes | Format-List
```

Expect `csharp.validate-property-assignment`, titled **Normalize and validate properties with the C# field keyword**, with a reusable goal about normalizing/validating setters without declaring a backing field. The full Markdown includes both warehouse implementations, four migration steps and recursion/initialization constraints. Applicability shows target 10.0, runtime .NET 10, C# 14, exact SDK baseline, prerequisites, source/evidence references and empty experimental opt-in/limitation arrays. Unresolved snippet tokens, missing Markdown/routes or discovery/detail disagreement indicate failure. Connections close automatically.
