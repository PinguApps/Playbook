# Component property policies, void interop and changing formulas

[PIN-801](https://linear.app/pinguapps/issue/PIN-801),
[PIN-802](https://linear.app/pinguapps/issue/PIN-802) and
[PIN-803](https://linear.app/pinguapps/issue/PIN-803) deliver one combined change:

- `blazor.customize-injected-properties/11.0`: explicit property policy with
  actual keyed/unkeyed services; .NET 10 uses a constructor-injected adapter.
- `blazor.use-void-interop-intent/11.0`: a no-result action uses InvokeVoidAsync;
  the same API already works in the actual older comparison.
- `blazor.render-mathematical-markup/11.0`: Razor owns dynamic MathML;
  the older working formula is a JavaScript-owned namespace-aware subtree.

All three recipes include the complete original BreakwaterLab comparison.
There is one canonical source per release, shared across these related goals.
The eight curated .NET 10 foundations and every existing goal/edition are retained.

The policy owns a deliberately closed application component set, not a general
container replacement. It explicitly assigns StationPanel's properties and
rejects other injected component types. Non-injected framework boundaries receive
a no-op. Adding an injected property to the known component requires updating the
mapping. No claim is made for general concurrent activation, Hot Reload, trimming,
NativeAOT, third-party containers or untested rendering modes.
