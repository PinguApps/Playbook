# PIN-782: act on a selected QuickGrid row

## Scope and criteria

Stable goal blazor.act-on-selected-row receives one 11.0 edition. Criteria 1–5
map to the original MuseumRows .NET 10/11 apps, complete canonical Markdown and
requirements, source-disposition row G14, actual compilation and existing packed
offline stdio harness. Criteria 6–8 map to the typed OnRowClick callback, correct
selected item and explicit static SSR exclusion. No new .NET 10 foundation or
conditional older-target callback route is introduced.

Read the full Linear issue, SPEC.md at its original source commit and current
version, WEB_W09B proposal, W/W5/WR2 inventory, Blazor API audit/dispositions,
contribution/dependency policies, PIN-772–775 evidence and installed harness.
These references agree on one interactive callback contract. PIN-781 owns URL
state and PIN-783 virtualization. No Linear writes, delegation, provisioning,
release, deployment or PR merge is performed.

The older supported alternative is an explicit TemplateColumn button, with real
keyboard execution. The newer row event is an additional pointer shortcut. Both
open the same original museum record locally. Keeping an accessible button and
stopping its bubbling avoids a duplicate action. The pinned official RC2 source
registers the event on tr and passes the item directly. Neither experimental
flags nor a down-level package route is claimed.

## Inspect what an agent receives

Adapted from [the Inspector walkthrough](../inspect-guidance.md). Requires
PowerShell 7, .NET SDK 10.0.402 and Node 22.19+. Setup uses public registries;
the built server serves embedded content. Verified starting from C:\Windows.

```powershell
& {
  Set-Location -LiteralPath 'V:\_worktrees\Playbook\agent-pin-782-04-010-interactive-quickgrid-row-selection'
  $ErrorActionPreference = 'Stop'
  $PSNativeCommandUseErrorActionPreference = $true
  $env:DOTNET_ADD_GLOBAL_TOOLS_TO_PATH = '0'
  $dotnet = 'C:\Program Files\dotnet\dotnet.exe'
  $node = 'C:\Program Files\nodejs\node.exe'
  & $dotnet build ./src/PinguApps.Playbook -c Release
  & $node 'C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js' install --prefix ./artifacts/inspector --ignore-scripts --no-audit --no-fund @modelcontextprotocol/inspector@2.11.0
  $inspector = (Resolve-Path ./artifacts/inspector/node_modules/@modelcontextprotocol/inspector/clients/launcher/build/index.js).Path
  $server = (Resolve-Path ./src/PinguApps.Playbook/bin/Release/net10.0/PinguApps.Playbook.dll).Path
  $call = { param($tool, $argument)
    & $node $inspector --cli --format json --quiet --method tools/call --tool-name $tool --tool-arg 'targetVersion="11.0"' --tool-arg $argument -- $dotnet $server mcp | ConvertFrom-Json
  }
  $list = & $call list_recipes 'query=museum-rows'
  if (@($list.result.structuredContent.recipes).Count -ne 1) { throw 'Expected the row-selection recipe' }
  $list.result.structuredContent.recipes | Format-List id, title, goal
  $recipe = (& $call get_recipe 'id=blazor.act-on-selected-row').result.structuredContent.recipe
  if (-not $recipe.markdown -or $recipe.markdown.Contains('{{snippet:') -or $recipe.edition -ne '11.0') { throw 'Incomplete recipe' }
  $recipe.markdown
  $recipe.applicability.routes | ConvertTo-Json -Depth 15
}
```

Expect blazor.act-on-selected-row, title **Open the chosen table item**, its discovery goal, the complete original .NET 10/11 comparison and
interactive-handler/static SSR constraints. Each Inspector call initializes and
closes the real stdio server. Missing content, unresolved snippets or wrong edition
fail. Compilation freshness is not proof of a consumer's actual environment.
