# PIN-669: release editions and applicability

The installed tools resolve .NET 10/11 aliases, retain release editions, disclose assumed targets and coverage limits, and return JSON failures through standard MCP `isError` results. Exactly two read-only tools remain. The stable property goal ID is unchanged.

## Acceptance evidence

1. **Aliases, defaults and coverage:** packed stdio calls cover `10`, `10.0`, `net10.0` and the three .NET 11 equivalents on both tools. Omission resolves to installed release `11.0` with `targetAssumed=true`. Discovery exposes supported targets, areas and example languages. Both tools disclose curated .NET 10 and the comprehensive .NET 11 launch commitment, explicitly incomplete.
2. **Retained editions and conditions:** explicit .NET 10/11 requests select editions `10.0`/`11.0` respectively, while `introducedIn` stays `10.0`. Responses include target-specific routes with runtime, SDK, language, framework, package assets, providers, platforms, rendering, prerequisites, constraints, source URLs and exact-target sample references. The real .NET 10 edition documents an optional .NET 11 SDK route retaining C# 14. Samples compile and execute against actual .NET 9, 10 and 11 targets; the newer-SDK/older-runtime route builds with SDK 11 and executes on runtime 10. No C# 15-on-.NET 10 compatibility is claimed.
3. **Failures:** packed calls check `unsupported_target` for .NET 9, a future release, patches, RC strings, platform-qualified TFMs and blank input, plus `unknown_recipe`. The exact requested target and supported releases survive. A separate packed fixture checks `no_applicable_edition` and available edition labels for a known .NET 11-only ID. Explicit targets are never replaced. JSON errors remain parseable without stripping SDK prose prefixes; success responses retain full structured/text equality and output schemas.
4. **Installed boundary:** four Reqnroll scenarios install newly packed artifacts into fresh local feeds, caches and stores, run outside the checkout, initialize stdio, invoke tools and close cleanly. The ordinary package has one goal with two editions. A separate unpublished fixture adds overlapping compatible editions, a known incompatible goal and synthetic pre-introduction metadata to exercise the resolver. The fixture proves metadata routing, not a .NET 11 API introduction. Its sample references use the actually compiled conditional route. Removing its conditional flag is rejected by content generation. .NET 9 remains comparison-only.
