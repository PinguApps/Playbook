## Evidence boundaries

Four actual console projects compile and execute under SDK 10.0.402/C# 14.0 and
11.0.100-rc.2.26504.105/C# 15.0. Record-Evidence captures exact SDK/runtime details,
package dependencies, commands, output and hashes. Shared protocol checks are
declared additional inputs. Usage snippets are compiled with their projects;
the check entry points execute controlled local operations, not arbitrary
application-supplied endpoints.

- HTTP/1.1: real TCP requests, wire headers/framing, gzip/br and RC2 zstd,
  compressed fixture size and exact original decompression; healthy connection
  reuse followed by finite-lifetime or callback-based idle reconnection.
- HTTP/2: real TCP prior-knowledge peer with delayed SETTINGS, two initial streams,
  advertised limit three, RC2 third-stream admission and no fourth while held;
  older application gate remains two. All six requests complete; zero is rejected.
  The 200 ms absence observation is bounded, not a scheduler proof/benchmark.
- DNS: real UDP queries to loopback (port 53 on Windows, ephemeral elsewhere) with unique names, original target/port/
  priority/weight/TTL, NXDOMAIN/NODATA, cancellation and Windows nonstandard-port
  rejection. This port must be free; the sample fails rather than reconfiguring
  or stopping any existing resolver. No machine DNS settings are changed.

These are Windows x64 authoring checks, not cross-compilation, mocks, external
service/TLS/proxy evidence, active-request abort, production DNS migration,
endpoint selection/connection, native UI/mobile/browser execution or GA proof.
Linux/macOS resolver contracts and active-request completion semantics are
source-reviewed. No required Human-only proof remains for the stated scope.
Offline Linux retrieval is a separate packed-consumer check, not sample execution.

## Reproduce focused behavior

Requires PowerShell 7 and the two pinned SDK installations. These checks bind
only local HTTP ports and UDP loopback (port 53 on Windows), and create ordinary ignored build output.

```powershell
Set-Location -LiteralPath 'V:\_worktrees\Playbook\t3-5a6b29b0'
$ErrorActionPreference = 'Stop'
$PSNativeCommandUseErrorActionPreference = $true
$env:DOTNET_ADD_GLOBAL_TOOLS_TO_PATH = '0'
foreach ($release in @('net10.0', 'net11.0')) {
  $dotnet = if ($release -eq 'net11.0') { 'C:\Users\pingu\.dotnet-playbook-11\dotnet.exe' } else { 'C:\Program Files\dotnet\dotnet.exe' }
  foreach ($family in @('HttpCapacity', 'DnsServices')) {
    Push-Location "samples/$release/$family"
    try { & $dotnet run -c Release -p:RestoreLockedMode=true }
    finally { Pop-Location }
  }
}
& ./eng/Test-DependencyPolicy.ps1
```

Expect four final PASS summaries, including the HTTP/2 check, exact DNS fields and
distinct negative outcomes, followed by dependency-policy PASS. A build/exception,
missing assertion or occupied DNS port is a failure. Dispose/exit stops the local
peers; no application data or external resources need cleanup.

## Inspect what an agent receives

Adapted from [the MCP Inspector walkthrough](../inspect-guidance.md).
Requires PowerShell 7, SDK 10.0.402 and Node 22.19+. Setup is online; the real
built stdio server then serves embedded guidance without fetching content.
The absolute paths below are the actual authoring installations. No global
installation, lifecycle script, shell integration, account or PATH change occurs.

```powershell
& {
  Set-Location -LiteralPath 'V:\_worktrees\Playbook\t3-5a6b29b0'
  $ErrorActionPreference = 'Stop'
  $PSNativeCommandUseErrorActionPreference = $true
  $env:DOTNET_ADD_GLOBAL_TOOLS_TO_PATH = '0'
  $dotnet = 'C:\Program Files\dotnet\dotnet.exe'
  $node = 'C:\Program Files\nodejs\node.exe'
  & $dotnet build ./src/PinguApps.Playbook -c Release
  & $node 'C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js' install --prefix ./artifacts/inspector --ignore-scripts --no-audit --no-fund @modelcontextprotocol/inspector@2.11.0
  $inspector = (Resolve-Path ./artifacts/inspector/node_modules/@modelcontextprotocol/inspector/clients/launcher/build/index.js).Path
  $server = (Resolve-Path ./src/PinguApps.Playbook/bin/Release/net10.0/PinguApps.Playbook.dll).Path
  $call = { param($tool, $argument)
    & $node $inspector --cli --format json --quiet --method tools/call --tool-name $tool --tool-arg 'targetVersion="11.0"' --tool-arg $argument -- $dotnet $server mcp | ConvertFrom-Json
  }
  $list = & $call list_recipes 'query=network-capacity'
  if (@($list.result.structuredContent.recipes).Count -ne 4) { throw 'Expected four network recipes' }
  $list.result.structuredContent.recipes | Format-List id, title, goal
  foreach ($entry in $list.result.structuredContent.recipes) {
    $detail = & $call get_recipe "id=$($entry.id)"
    $recipe = $detail.result.structuredContent.recipe
    $recipe | Format-List id, edition, introducedIn, stability
    $recipe.markdown
    $recipe.applicability.routes | ConvertTo-Json -Depth 15
  }
}
```

Expect exactly four ID/title/goal summaries, full original comparisons and
applicability for edition/target 11.0. Eviction must disclose experimental
SYSLIB5008; DNS must disclose Windows port/family and failure handling. Missing
Markdown, unresolved snippet tokens or unsupported older-target recommendations
are failures. Each Inspector call initializes and closes the real built server.
The installed-package scenario separately checks full rendered bodies against
independently embedded canonical inputs, JSON text/structured equality,
applicability, evidence freshness and .NET 10 rejection using the existing
isolated local feed/cache and unrelated working directory.
