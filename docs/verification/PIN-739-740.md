## Criteria, sources and decisions

All four original editions preserve the inventory IDs, introduce/support only
target 11.0 and compare actual .NET 10 and 11 projects. They add no .NET 10
foundation or speculative older-target route. Markdown uses canonical snippets,
complete offline steps, metadata, official sources and explicit requirements.

- Bit constructors cover bool/byte/int spans, copied storage, exact bit positions,
  counts, truncation, inverted tails and an empty collection.
- Key selection covers case-sensitive/default and ordinal case-insensitive
  equality, matching hashes, null keys, distinct groups and independently chosen
  ordering with ticket tie-breaks. No provider translation is claimed.
- Vector128 lane checks cover zip/unzip, four concat variants, reverse and
  geometric/alternating/floating-harmonic construction, with the same results
  when hardware intrinsics are disabled.
- Instruction checks compile the actual signed SVE predicate and V512 VNNI code.
  On this host only AVX2 and scalar paths execute. They agree with independent
  scalar calculations at empty, partial, exact and multiple vector lengths,
  including overflow. Required advanced-path modes fail explicitly here.
- The existing packed-tool scenario checks complete original bodies, exact
  snippets, structured/text equality, discovery goals, applicability, edition
  safety, experimental opt-ins and the preserved pending-proof status. This is
  retrieval evidence, not native instruction execution.

Sources: both full target issues and their empty comments/attachments; SPEC.md
at `0a8989814ea11346354464b845c79c15bb71c5e9` and current SPEC.md; approved
proposal `b3778cc`, keys SH_N06/SH_N07; implementation/coverage/verification plans,
glossary, ADRs 0001–0004, contribution/evidence contract, dependency policy and
the data/I/O API audit. Root PLAN.md, CONTEXT.md and CONTEXT-MAP.md are absent.
Explicit target provenance pointers were resolved. Historical planning claims
that implementation has not started are stale; the existing consumer harness
is the agreed installed-package seam.

Related Linear reads that changed delivery: boundary-verified PIN-668 confirms
the existing completed packed-tool prerequisite; PIN-678 and its comments leave
the advanced-hardware route explicitly with Pingu even though that assessment
is Done. No related Linear issue was created or changed.

Official reference review uses the .NET 11 library/runtime release guidance and
actual immutable RC2 VMR `820230c386db5b0106c5430b3e5aee92a7826bf5` sources.
Metadata inspection resolves an important naming difference: RC2 has Sve,
Sve2, SveSha3 and SveSm4; there is no separate SveAes reference type. All four
SVE types carry ExperimentalAttribute SYSLIB5003. XML documentation retains
older mask names and omits some newer declarations, so actual reference metadata
and compilation determine callable names. AvxVnni.V512 is the reviewed exact
512-bit contract, with a separate IsSupported check. Its execution is pending.

The six new sample projects inherit only samples/ build/package boundaries.
They have exact SDK/language pins and no package/workload dependencies. The
new SVE project sets AllowUnsafeBlocks and scopes SYSLIB5003 suppression to
its sample file. Root consumer versions/frameworks and Renovate permissions
stay unchanged; samples remain author-maintained under the existing default
manual policy. Both policy checks are required for these project additions.

## Inspect what an agent receives

Adapted from [the Inspector walkthrough](../inspect-guidance.md). PowerShell
7.3+, SDK 10.0.402 and Node 22.19+ are required. Setup downloads pinned
Inspector 2.11.0 with lifecycle scripts disabled; server calls use embedded
content and need no network. Each Inspector invocation shuts down its server.

```powershell
& {
  $ErrorActionPreference = 'Stop'
  $PSNativeCommandUseErrorActionPreference = $true
  Set-Location -LiteralPath 'V:\_worktrees\Playbook\t3-dbe39d02'
  $env:DOTNET_ADD_GLOBAL_TOOLS_TO_PATH = '0'
  $dotnet = 'C:\Program Files\dotnet\dotnet.exe'
  & $dotnet build ./src/PinguApps.Playbook -c Release
  & 'C:\Program Files\nodejs\npm.cmd' install --prefix ./artifacts/inspector-2.11.0 --ignore-scripts --no-audit --no-fund --package-lock=false @modelcontextprotocol/inspector@2.11.0
  $server = (Resolve-Path ./src/PinguApps.Playbook/bin/Release/net10.0/PinguApps.Playbook.dll).Path
  $inspector = (Resolve-Path ./artifacts/inspector-2.11.0/node_modules/@modelcontextprotocol/inspector/clients/launcher/build/index.js).Path
  $call = { param($tool, $argument)
    & 'C:\Program Files\nodejs\node.exe' $inspector --cli --format json --quiet --method tools/call --tool-name $tool --tool-arg 'targetVersion="11.0"' --tool-arg $argument -- $dotnet $server mcp | ConvertFrom-Json
  }
  foreach ($id in @('collections.count-and-build-bits','collections.compare-by-key','simd.arrange-lanes','simd.select-supported-instructions')) {
    $list = & $call list_recipes "query=$($id.Split('.')[1])"
    $list.result.structuredContent.recipes | Format-List id, title, goal, stability
    $detail = & $call get_recipe "id=$id"
    $recipe = $detail.result.structuredContent.recipe
    $recipe | Format-List id, edition, introducedIn
    $recipe.markdown | Show-Markdown
    $recipe.applicability.routes | ConvertTo-Json -Depth 15
    $recipe.humanProof | Format-List
  }
}
```

Expected: four ID/title/goal summaries, edition/introduction 11.0, complete
canonical .NET 10/11 comparisons and selected applicability. The instruction
summary/detail are experimental with SYSLIB5003 opt-in and humanProof=pending;
the other three are stable with no required Human action. Missing bodies,
unresolved snippet tokens, absent applicability or a false verified native
claim are failures. Installed tests also require target-10 discovery to omit
these editions and explicit target-10 get to return no_applicable_edition.

## Required native handoff

There is no currently available route. Do not provision resources or change
hardware requirements implicitly. To resume, use the same source/input hashes,
declared SDK/runtime and sample on a suitable isolated measured host. Run the
canonical sample in its required mode and retain feature flags and scalar
agreement output. SVE2/SHA3/SM4 reporting establishes detection only; no
cryptographic or general SVE2 algorithm is claimed by these examples.

The current .NET 11 DLL accepts --require-sve and --require-vnni512. Both exit
nonzero with INCOMPLETE on the available host. A plain PASS establishes only
the paths named in its output. Required native results must be captured and
reviewed before changing humanProof to verified, refreshing affected inputs,
rebuilding/retesting and publishing the combined PR. RC2 evidence is not GA
verification. No mocks or cross-compilation replace this missing execution.
