## Measured source differences and limits

- The public RC2 SDK's bare `UseRuntimeAsync=true` does not enable C# runtime async.
  Explicit `Features=runtime-async=on/off` does change emitted lowering. The
  property is meaningful in upstream repositories that translate it themselves;
  the recipe does not silently invent that mapping for a consumer.
- Runtime async reports cleaner live frames in this bounded observation. Both
  thrown-exception variants preserve the originating survey method; there is no
  universal stack/debugger guarantee. Removed environment variables set to zero
  do not disable already marked methods.
- Actual lifetime rejection is FS3919, while the matching F# document says FS3917.
  A pending generic Task upcast to non-generic Task produced InvalidProgramException
  during authoring. The bounded supported unit sample uses a real non-generic Task;
  the limitation remains explicit in discovery/detail. No AOT or production-complete
  builder is claimed. No unsupported path is presented as a verified route.
- The .NET 10 reference pack exposes some experimental runtime-async metadata.
  This does not prove a supported older application/runtime route; none is offered.
  The negative runtime-capability check deliberately uses .NET 9 references.
- FCS opt-out is a hosted correctness/configuration decision, not a memory cap or
  universal benchmark claim. No public ClearCaches method is advertised.

Saved evidence/locks are small and meaningful review inputs, so the
`pragent-ignore` assessment keeps them reviewable. No exclusion rules change.
Compilation/execution are real managed checks, not mocks or cross-compilation.
Native AOT, IDE stepping, browser/Mono, other-platform execution and final GA proof
are outside the claims. No missing targeted Human proof remains for these claims.

## Inspect what an agent receives

Adapted from [the MCP Inspector walkthrough](../inspect-guidance.md). Requires
PowerShell 7, SDK 10.0.402 and Node 22.19+. Online setup installs pinned Inspector
under ignored artifacts; the built server supplies embedded guidance. This block
is verified from C:\Windows before selecting the literal task worktree.

```powershell
& {
  Set-Location -LiteralPath 'V:\_worktrees\Playbook\t3-4a1b7035'
  $ErrorActionPreference = 'Stop'
  $PSNativeCommandUseErrorActionPreference = $true
  $env:DOTNET_ADD_GLOBAL_TOOLS_TO_PATH = '0'
  $dotnet = 'C:\Program Files\dotnet\dotnet.exe'
  $node = 'C:\Program Files\nodejs\node.exe'
  & $dotnet build ./src/PinguApps.Playbook -c Release
  & $node 'C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js' install --prefix ./artifacts/inspector --ignore-scripts --no-audit --no-fund @modelcontextprotocol/inspector@2.11.0
  $inspector = (Resolve-Path ./artifacts/inspector/node_modules/@modelcontextprotocol/inspector/clients/launcher/build/index.js).Path
  $server = (Resolve-Path ./src/PinguApps.Playbook/bin/Release/net10.0/PinguApps.Playbook.dll).Path
  $call = { param($tool, $target, $argument)
    & $node $inspector --cli --format json --quiet --method tools/call --tool-name $tool --tool-arg $target --tool-arg $argument -- $dotnet $server mcp | ConvertFrom-Json
  }
  $list = & $call list_recipes 'targetVersion="11.0"' 'query=runtime-compiler-hosts'
  if (@($list.result.structuredContent.recipes).Count -ne 3) { throw 'Expected three recipes' }
  $list.result.structuredContent.recipes | Format-List id, title, goal, stability
  foreach ($entry in $list.result.structuredContent.recipes) {
    $recipe = (& $call get_recipe 'targetVersion="11.0"' "id=$($entry.id)").result.structuredContent.recipe
    $recipe | Format-List id, edition, stability
    $recipe.markdown
    $recipe.applicability.routes | ConvertTo-Json -Depth 15
  }
  $older = (& $call get_recipe 'targetVersion="10.0"' 'id=fsharp.configure-compiler-service-memory').result.structuredContent.recipe
  $older | Format-List id, edition, introducedIn
  $older.applicability.routes | ConvertTo-Json -Depth 15
}
```

Expect three reusable ID/title/goal summaries, two experimental recipes and one
preview-package recipe, full comparisons/support and target-11 applicability.
The final detail retains edition/introduction 11.0 with conditional target-10
requirements for the new FCS package. Missing body, unresolved snippet tokens,
missing constraints or an older runtime-async route is a failure. Inspector closes
each real server automatically. This proves what is served, not application
compatibility, profiler integration or GA behavior.
