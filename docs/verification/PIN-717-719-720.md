# PIN-717, PIN-719 and PIN-720: F# API boundaries and asynchronous work

Eight original edition **11.0** recipes retain their planned stable IDs. Four cover API authoring, three cover asynchronous work, and one covers the enum migration. Ten independent executable projects compare **.NET 10 / F# 10** with **.NET 11 RC2 / F# 11 or preview**. No new .NET 10 catalogue editions, older-target routes, host features or OS/client matrices are introduced.

## Requirement coverage

- **PIN-717 (L/5):** `fsharp.pass-methods-as-delegates`, `fsharp.adapt-generic-operations`, `fsharp.require-named-arguments`, `fsharp.reuse-api-documentation`. `FSharpApi` verifies delegate invocation and actual generated XML: `<include>` expands the external summary; `<inheritdoc>` remains a tag. `FSharpApiPreview` verifies a public SRTP instance extension and reordered named calls, checks that the attribute is supplied by its own assembly, and checks its absence from the pinned runtime BCL. External consuming builds independently require the extension module and preview mode, reject positional calls with **FS3923**, and accept them under default F# 11 where enforcement is absent. The supplied attribute source and external XML are included in the served Markdown.
- **PIN-719 (L/5):** `fsharp.start-async-on-caller`, `fsharp.bound-async-work`, `fsharp.rethrow-in-computations`. `FSharpAsync` gates work before factory invocation, holds the first two operations at a barrier, measures peak concurrency **2**, and checks input-order results **10, 20, 30, 40** for async and task paths. It also verifies task sibling-token cancellation after a failure, caller-prefix thread identity and the ambient-context restriction below. Both `FSharpRethrow` comparisons suspend before failing and assert the original no-inline `failAtDock` frame for async and task. Stable F# 11 rejects the newer handler with **FS3350**; preview executes it. The older `ExceptionDispatchInfo` route remains valid.
- **PIN-720 (S/2):** `fsharp.migrate-enum-flags`. The actual F# 10 char-enum OR/AND/XOR expressions compile and each throws **NotSupportedException**. Separate F# 11 builds independently reproduce **FS0001** for all three. The integer replacement verifies permission combination/membership/toggling and OR/AND/XOR for all **64** pairs of three-bit values. There was no working char-backed flags behavior to preserve; the recipe preserves the intended independent permissions and calls out wire/storage migration.
- **Common criteria:** original fictional harbour examples; fair previous-release comparisons; canonical snippet expansion; full offline metadata and Markdown; official references; exact SDK/language/package/asset evidence; explicit provider/platform/workload/rendering/stability requirements; experimental labels for SRTP, named enforcement and computation rethrow; source-register dispositions; and current compilation/execution records. The existing packed-tool F# scenario checks discovery, complete body equality against independent canonical resources, structured/text equality, applicability, target/edition, current evidence and .NET 10 rejection for all eight additions.

Actual artifacts settle these details:

- RC2 BCL has no `System.Diagnostics.CodeAnalysis.RequireNamedArgumentsAttribute`; the full independently authored definition is compiled before the annotated API. Enforcement is a caller-side F# preview rule, not runtime or C# validation.
- Direct delegate spelling also compiles on F# 10. The canonical older executable demonstrates both an explicit adapter and that spelling; the newer executable verifies direct binding to DockMath.Remaining rather than the older generated Invoke wrapper. This is compiler-lowering evidence, not an allocation/performance benchmark or a claim of new syntax. Existing direct calls need no rewrite.
- The XML test inspects the emitted file rather than inferring IDE tooltips. IDE/FCS tooltip and documentation-site rendering are not claimed.
- **SynchronizationContext source/artifact mismatch:** RC1 notes and the pinned FSharp.Core XML say the runner disregards the ambient context. Actual RC2 execution posts **once** to a recording context after `Async.Sleep`. The sample checks that behavior directly and its reusable wrapper rejects an ambient context. It starts the prefix on the caller with no context and resumes elsewhere after suspension. This blocking API is not presented as UI-safe. GA reconciliation must revisit the mismatch.
- SRTP's instance-method extension requires preview and the defining module at the external call site. The sample does not generalize its successful shape to every property/operator/overload.

## Inspect what an agent receives

Adapted from [the MCP Inspector walkthrough](../inspect-guidance.md). Requires PowerShell 7.3+, the pinned host SDK and Node 22.19+. This calls both real built-server tools, displays reusable discovery descriptions, full Markdown and applicability, and shuts each server down automatically. Run from any unrelated directory; the first location command selects this exact worktree.

```powershell
& {
  $ErrorActionPreference = 'Stop'
  $PSNativeCommandUseErrorActionPreference = $true
  Set-Location -LiteralPath 'V:\_worktrees\Playbook\t3-51336f72'
  $env:DOTNET_ADD_GLOBAL_TOOLS_TO_PATH = '0'
  $dotnet = 'C:\Program Files\dotnet\dotnet.exe'
  & $dotnet build ./src/PinguApps.Playbook -c Release
  & 'C:\Program Files\nodejs\npm.cmd' install --prefix ./artifacts/inspector-2.11.0 --no-audit --no-fund --package-lock=false @modelcontextprotocol/inspector@2.11.0
  $server = (Resolve-Path ./src/PinguApps.Playbook/bin/Release/net10.0/PinguApps.Playbook.dll).Path
  $inspector = (Resolve-Path ./artifacts/inspector-2.11.0/node_modules/@modelcontextprotocol/inspector/clients/launcher/build/index.js).Path
  $ids = @('pass-methods-as-delegates', 'adapt-generic-operations', 'require-named-arguments', 'reuse-api-documentation', 'start-async-on-caller', 'bound-async-work', 'rethrow-in-computations', 'migrate-enum-flags') | ForEach-Object { "fsharp.$_" }
  $cli = @('--cli', '--format', 'json', '--quiet')
  $catalogue = & 'C:\Program Files\nodejs\node.exe' $inspector @cli --method tools/call --tool-name list_recipes --tool-arg 'targetVersion="11.0"' --tool-arg 'languages=["fsharp"]' -- $dotnet $server mcp | ConvertFrom-Json
  $catalogue.result.structuredContent.recipes | Where-Object id -In $ids | Format-List id, title, goal, stability
  foreach ($id in $ids) {
    $response = & 'C:\Program Files\nodejs\node.exe' $inspector @cli --method tools/call --tool-name get_recipe --tool-arg "id=$id" --tool-arg 'targetVersion="11.0"' -- $dotnet $server mcp | ConvertFrom-Json
    $recipe = $response.result.structuredContent.recipe
    $recipe | Format-List id, edition, introducedIn
    $recipe.markdown | Show-Markdown
    $recipe.applicability.routes | ConvertTo-Json -Depth 15
  }
}
```

Expect eight summaries with ID/title/goal/stability, all edition/introduction **11.0**, full original .NET 10/11 code and explicit applicability. SRTP, named enforcement and rethrow are experimental/preview. Named enforcement includes its supplied definition; documentation includes its external XML; caller-start includes the context guard and measured mismatch. Missing body/applicability, unresolved snippet tokens or silent .NET 10 compatibility is a failure.
