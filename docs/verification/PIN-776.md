## Reconciliation and decisions

The original harbour permit example uses .NET 10's valid MVC TempData bridge and
explicit ISession, versus .NET 11 ITempData and supplied properties. No guide
implementation was copied. SDK pins/language modes are evidence baselines;
consumer requirements use release families where appropriate. Both APIs are
stable contracts with RC2 execution, no experimental opt-in and GA pending.

**Measured RC2 behavior:** an unchanged SupplyParameterFromTempData property
writes its received value back, repeating the message on the second request.
The reader copies the value for display and sets the bound property to null.
The initial failing sequential read reproduced this issue; the final checks
prove one-use display with cookie and session-storage TempData. The pinned
TempDataCascadingValueSupplier.PersistValues source corroborates the write-back.
Direct ITempData reads consume unless Peek/Keep is chosen deliberately.

Session values survive reads. Static SSR requires both session services and
middleware. An early subscription establishes a fresh cookie before streaming;
the late value is saved after rendering. Cookie TempData cannot persist late
writes; the session-storage provider can, with early session setup. These are
explicit applicability constraints, not extra recipes per overload.

Samples inherit only samples/Directory.Build.props and Directory.Packages.props,
not root tool packages. Web SDK Internal.Assets versions are locked at 10.0.13
and 11.0.0-rc.2.26504.105; no new PackageReference or automatic Renovate permission
is added. Root production host/test targets remain net10.0 and workload-free.
The test project embeds new canonical inputs only. All evidence/lockfiles are
small and reviewable; pragent-ignore assessment adds no exclusion.

## Inspect what an agent receives

Adapted from [the MCP Inspector walkthrough](../inspect-guidance.md). Requires
PowerShell 7, .NET SDK 10.0.402 and Node 22.19+. Setup downloads Inspector; the
built server serves embedded guidance without network retrieval. This exact
block is tested from C:\Windows, selecting the assigned worktree first:

```powershell
Set-Location -LiteralPath 'V:\_worktrees\Playbook\agent-pin-776-04-004-author-ssr-redirect-and-session-state-workflows'
$ErrorActionPreference = 'Stop'
$PSNativeCommandUseErrorActionPreference = $true
$env:DOTNET_ADD_GLOBAL_TOOLS_TO_PATH = '0'
$dotnet = 'C:\Program Files\dotnet\dotnet.exe'
$node = 'C:\Program Files\nodejs\node.exe'
& $dotnet build ./src/PinguApps.Playbook -c Release
& $node 'C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js' install --prefix ./artifacts/inspector --ignore-scripts --no-audit --no-fund @modelcontextprotocol/inspector@2.11.0
$inspector = (Resolve-Path ./artifacts/inspector/node_modules/@modelcontextprotocol/inspector/clients/launcher/build/index.js).Path
$server = (Resolve-Path ./src/PinguApps.Playbook/bin/Release/net10.0/PinguApps.Playbook.dll).Path
$call = { param($tool, $argument)
  & $node $inspector --cli --format json --quiet --method tools/call --tool-name $tool --tool-arg 'targetVersion="11.0"' --tool-arg $argument -- $dotnet $server mcp | ConvertFrom-Json
}
$list = & $call list_recipes 'query=harbour-state'
if (@($list.result.structuredContent.recipes).Count -ne 2) { throw 'Expected two state recipes' }
$list.result.structuredContent.recipes | Format-List id, title, goal
$inspection = Join-Path (Get-Location) 'artifacts/inspected-harbour'
New-Item -ItemType Directory -Path $inspection -Force | Out-Null
foreach ($entry in $list.result.structuredContent.recipes) {
  $recipe = (& $call get_recipe "id=$($entry.id)").result.structuredContent.recipe
  if (-not $recipe.markdown -or $recipe.markdown.Contains('{{snippet:') -or $recipe.edition -ne '11.0' -or -not $recipe.applicability.routes) { throw 'Incomplete recipe' }
  $recipe | Format-List id, edition, stability
  $recipe.markdown
  [IO.File]::WriteAllText((Join-Path $inspection "$($entry.id).md"), $recipe.markdown)
  $recipe.applicability.routes | ConvertTo-Json -Depth 15
}
```
