# PIN-793: reuse a browser build with public configuration

[PIN-793](https://linear.app/pinguapps/issue/PIN-793/04-021-reuse-one-browser-build-across-environments)
delivers the original blazor.supply-browser-configuration goal, edition 11.0.
EstuaryBoard compares actual .NET 10 explicit environment-provider registration
with the .NET 11 default provider. G23/WEB-023 and grouped WEB-098 retain their
identity. This adds no .NET 10 foundation or browser startup-policy goal.

Initial T3 binding, actual path/branch, clean HEAD and freshly fetched origin/main
matched 4c6e72d812c0297af01a95a5f958a602cafc2dad. The exact same-named origin
branch/upstream/SHA were verified before edits. No Linear writes, nested agents,
accounts/resources, deployment, release or package publication are involved.

## Source and compatibility

The [release notes](https://learn.microsoft.com/en-us/aspnet/core/release-notes/aspnetcore-11?view=aspnetcore-11.0#environment-variables-in-blazor-webassembly-configuration)
describe automatic browser environment configuration. The pinned RC2 builder
constructs its instance, loading base and environment JSON, before CreateDefault
adds AddEnvironmentVariables. The older builder lacks that default registration.
Actual restored package/browser execution, rather than source alone, establishes
the sample's ordering. [Source identities](PIN-793.sources.json) distinguish
official review from compilation and real browser proof.

Both standalone projects declare all settings, package boundaries/pins, namespace
and imports, document, CSS, JS, JSON and local host. Node 24.21.0 serves only
loopback fixtures. The .NET 10 project explicitly references the compatible
10.0.13 environment package; RC2 supplies its provider transitively. No DevServer,
Gateway, native workload or worker is needed. PublishTrimmed=false records an
untrimmed interpreted route, not AOT. New sample dependencies remain manually
maintained; no Renovate permission or maintained root-consumer boundary changes.

The APIs require no Experimental diagnostic opt-in in these actual artifacts.
RC2 remains prerelease evidence; GA, production CDN delivery, hosted/Auto and
server rendering are outside the execution claim. All settings are public and
modifiable by the browser user. No hosting-machine OS variables are transferred
implicitly and no fictional endpoint is contacted.

## Inspect what an agent receives

Adapted from [the Inspector walkthrough](../inspect-guidance.md). Requires
PowerShell 7, SDK 10.0.402 and Node 22.19+ at the explicit paths below. Setup is
online; guidance itself is embedded and offline. This exact block is tested from
unrelated C:\Windows. It prints ID/title/goal, full Markdown, edition, complete
applicability, sources and current compilation evidence via the real stdio server.

```powershell
Set-Location -LiteralPath 'V:\_worktrees\Playbook\agent-pin-793-04-021-reuse-one-browser-build-across-environments'
& {
  $ErrorActionPreference = 'Stop'
  $PSNativeCommandUseErrorActionPreference = $true
  $env:DOTNET_ADD_GLOBAL_TOOLS_TO_PATH = '0'
  $dotnet = 'C:\Program Files\dotnet\dotnet.exe'
  $node = 'C:\Program Files\nodejs\node.exe'
  & $dotnet build ./src/PinguApps.Playbook -c Release -p:Version=0.0.0-pin793
  & $node 'C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js' install --prefix ./artifacts/inspector --ignore-scripts --no-audit --no-fund @modelcontextprotocol/inspector@2.11.0
  $inspector = (Resolve-Path ./artifacts/inspector/node_modules/@modelcontextprotocol/inspector/clients/launcher/build/index.js).Path
  $server = (Resolve-Path ./src/PinguApps.Playbook/bin/Release/net10.0/PinguApps.Playbook.dll).Path
  $call = { param($tool, $argument)
    & $node $inspector --cli --format json --quiet --method tools/call --tool-name $tool --tool-arg 'targetVersion="11.0"' --tool-arg $argument -- $dotnet $server mcp | ConvertFrom-Json
  }
  $entry = (& $call list_recipes 'query=estuary-config').result.structuredContent.recipes
  if ($entry.id -ne 'blazor.supply-browser-configuration') { throw 'Missing discovery' }
  $entry | Format-List id, title, goal
  $recipe = (& $call get_recipe 'id=blazor.supply-browser-configuration').result.structuredContent.recipe
  if ($recipe.edition -ne '11.0' -or -not $recipe.markdown -or $recipe.markdown.Contains('{{snippet:')) { throw 'Incomplete recipe' }
  $recipe | Format-List id, edition, stability
  $recipe.markdown
  $recipe.applicability.routes | ConvertTo-Json -Depth 30
  $recipe.sources | Format-Table
  $recipe.evidence | Format-List
}
```

Expect **Reuse a browser build**, goal **Supply public WASM settings per
environment; preserve provider precedence.**, edition 11.0, full original old/new
projects and shared setup, one WASM route and current compilation evidence.
Wrong edition, missing discovery/body or unresolved snippets fail. Each call
shuts down its server. The packed harness additionally rejects target 10.0 and
independently DeepEquals every authored route property, including all nested
requirements, prerequisites, constraints, assets, platform/rendering/stability,
source and evidence fields; it checks complete canonical JSON and Markdown.
