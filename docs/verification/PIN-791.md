## Source and compatibility reconciliation

[Pinned source hashes](PIN-791.sources.json) record official source review.
Microsoft's [release notes](https://learn.microsoft.com/en-us/aspnet/core/release-notes/aspnetcore-11?view=aspnetcore-11.0#ihostedservice-support-in-blazor-webassembly)
describe IHostedService support. The actual RC2 WebAssemblyHost calls its executor
after culture loading; DisposeAsync awaits StopAsync before renderer/provider
disposal. RunAsync takes no public cancellation token and normally never ends.
Page termination does not guarantee disposal. The original example therefore
owns an explicit live-document shutdown call, without an unload promise.

The actual .NET 10 host lacks that integration. Its sample still registers
IHostedService, then explicitly starts/stops the registrations. Its separate
registration-only negative control renders a working counter but never starts
the service. This is compatible older evidence, not .NET 11 cross-compilation.

Both samples declare complete standalone project settings, namespaces/imports,
document, CSS, JS, exact SDK/package pins and lock files. Interpreted WASM needs
no native compiler or wasm-tools workload. The .NET 10 sample explicitly
references Hosting.Abstractions; .NET 11 supplies it through its reference set,
and a redundant reference fails NU1510. RC2 DevServer remains runnable but emits
its deprecation warning recommending a future Gateway migration. That separate
hosting change is outside this ticket. The production tool remains net10.0 and
workload-free. New sample packages remain author-maintained; no Renovate grant
is added. Test project changes embed only own canonical files. Existing root
consumer inventory and protected update policy are preserved.
