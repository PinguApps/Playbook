## Inspect what an agent receives

Requires PowerShell 7, SDK 10.0.402 and Node 22.19+. Inspector 2.11.0 downloads its client on first use. Each call initializes and closes the real built server; no background service remains. The .NET 9/11 SDKs are needed to rerun samples, not to retrieve guidance.

```powershell
Set-Location V:\_worktrees\Playbook\t3-d20be884
$env:PATH = 'V:\_Scratch\upload-intake-pwsh;' + $env:PATH
dotnet build ./src/PinguApps.Playbook -c Release
if ($LASTEXITCODE -ne 0) { throw 'Build failed.' }
$server = (Resolve-Path ./src/PinguApps.Playbook/bin/Release/net10.0/PinguApps.Playbook.dll).Path
$inspector = @('--yes', '@modelcontextprotocol/inspector@2.11.0', '--cli', '--format', 'json', '--quiet')
$canonicalMarkdown = $null
foreach ($target in @('10.0', '11.0')) {
  $targetArg = 'targetVersion="' + $target + '"'
  $list = npx @inspector --method tools/call --tool-name list_recipes --tool-arg $targetArg -- dotnet $server mcp | ConvertFrom-Json
  $list.result.structuredContent.recipes | Format-List id, title, goal, edition, introducedIn
  $detail = npx @inspector --method tools/call --tool-name get_recipe --tool-arg id=csharp.validate-property-assignment --tool-arg $targetArg -- dotnet $server mcp | ConvertFrom-Json
  $recipe = $detail.result.structuredContent.recipe
  $detail.result.structuredContent | Format-List requestedTarget, resolvedTarget
  $recipe | Format-List id, edition, introducedIn, supportedTargets
  $recipe.markdown | Show-Markdown
  $recipe.applicability.routes | ConvertTo-Json -Depth 10
  $recipe.evidence | Format-Table role, sample, target, sdk, language, freshness -Wrap
  if ($recipe.edition -ne '10.0' -or $recipe.introducedIn -ne '10.0') { throw 'Shared edition/introduction changed.' }
  if ($canonicalMarkdown -and $recipe.markdown -cne $canonicalMarkdown) { throw 'Guidance differs between targets.' }
  if (@($recipe.applicability.routes | Where-Object target -ne $target).Count) { throw 'Wrong-target route returned.' }
  $canonicalMarkdown = $recipe.markdown
}
```

Expect one discovery ID, `csharp.validate-property-assignment`, titled **Normalize and validate properties with the C# field keyword**, with its explanatory `goal`. Both requests return edition/introduction `10.0` and the same warehouse Markdown with both compiled snippets, migration, initialization constraints and alternatives. Target `10.0` has two routes (primary SDK 10 and optional SDK 11), both on runtime 10; target `11.0` has one primary route for runtime/SDK 11, retaining C# 14 and RC limitations. Evidence keeps SDKs `10.0.402` and `11.0.100-rc.2.26504.105` as test baselines. A selected edition `11.0`, different Markdown or a wrong-target route is a failure.

To inspect the installed artifact, follow [local installation](../contributing.md#inspect-the-development-package) and replace `dotnet $server mcp` with `./artifacts/manual-tool/playbook.exe mcp`. Installed-package automation already exercises the actual package with fresh feeds/caches/stores outside the checkout.
