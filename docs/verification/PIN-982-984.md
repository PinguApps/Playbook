## Acceptance coverage and observed differences

**Array migration:** all three Based allocations become unbased allocation plus
explicit offsets. Original lower bounds, translated indexed mapping, empty first/
second/both dimensions, values and copy independence are checked. The same based
JIT comparison is compiled/executed against the newer selected asset too. Real
Native AOT analysis rejects ZeroCreateBased/CreateBased/InitializeBased with
IL3050 errors even for literal zero bases. The supported zero-based program is
published and executed as a native Windows x64 PE, with warnings as errors and
no suppression. The supplemental record hashes the executable and checks that
it has no managed metadata. Unannotated helper methods do not promise arbitrary
based-array AOT support. A plain chart class and concrete integer formatting
avoid unrelated record/printf reflection roots encountered during authoring.

**FSI:** real previous/current `dotnet fsi --exec` processes record loaded location,
target attribute and hash. Gated IAsyncDisposable cleanup runs once and completes
before script completion in all four body-success/failure and cleanup-success/
failure cases. The previous SDK's direct asynchronous Using binding fails FS0001;
its explicit awaited cleanup alternative succeeds. That same unchanged explicit
alternative also executes on the newer FSI. The newer ordinary task binding waits
for pending disposal but **loses a subsequent cleanup failure**: a successful body
returns its value and a failed body retains its exception. Explicit cleanup
propagates a cleanup failure, taking precedence over a body failure. This measured
RC2 limitation is in discovery constraints and detail. No new Using overload,
preview requirement, top-level async use or interactive AOT is claimed.

**Sequence:** original minimal inline support uses actual __runtimeAsyncSequence
and __runtimeAsyncSequenceCancellationToken intrinsics. It compiles and executes
with genuinely pending moves, incremental results, normal exhaustion, pending
early disposal, nested token propagation/cancellable waiting, non-cancellable
waiting followed by a token check, and pending nested/exceptional cleanup. Outer
cleanup failures replace inner cleanup failures; inner cleanup failures replace
body failures; successful cleanup preserves body exception identity. A small
serial adapter rejects overlapping moves/disposal before entering unsupported
raw iterator state. It makes no performance claim. Opaque recipes and optimized
tail handoff fail FS3922; missing preview and runtime-reference support fail
FS3350/FS3351. No shipped general-purpose builder, TaskSeq substitute, full
debugger stepping, .NET 10 runtime-async route or Native AOT support is claimed.

## Reproduce focused authoring verification

Requires PowerShell 7, the declared SDKs and Windows native tools above. The
negative script uses disposable temporary projects and cleans them up; it never
publishes or provisions resources. Each sample has a pinned SDK, isolated central
package boundary, lockfile, verification manifest and fresh evidence record.

```powershell
Set-Location -LiteralPath 'V:\_worktrees\Playbook\t3-d1f12b9c'
$env:DOTNET_ADD_GLOBAL_TOOLS_TO_PATH = '0'
& ./eng/Inspect-FSharpContracts.ps1 -CompareWith ./docs/verification/PIN-681.assets.json -OutputPath ./artifacts/pin-982-984/contracts.json
& ./eng/Test-FSharpLifetimes.ps1
foreach ($target in 'net10.0', 'net11.0') {
  $hostPath = if ($target -eq 'net10.0') { 'C:\Program Files\dotnet\dotnet.exe' } else { 'C:\Users\pingu\.dotnet-playbook-11\dotnet.exe' }
  foreach ($name in 'FSharpArrayAot', 'FSharpFsiCleanup', 'FSharpSequence') {
    $arguments = @{ Sample = "samples/$target/$name/$name.fsproj"; Dotnet = $hostPath }
    if ($target -eq 'net11.0' -and $name -eq 'FSharpArrayAot') {
      $arguments.NativeToolchains = @('MSVC/14.51.36231', 'WindowsSDK/10.0.26100.0')
    }
    & ./eng/Record-Evidence.ps1 @arguments
  }
}
```

Expect named PASS results, four expected compiler rejections and all three IL3050
call-site errors, followed by successful managed/FSI/native sample evidence.
The expected negative compiler output is not a failed authoring run. The newer
array verification property publishes without rebuilding recursively and runs
the actual native executable inside the captured build output. A later managed
DLL execution is separately recorded; it is not the native execution proof.
No OS/client/native matrix is added. Five managed sample paths join the existing
full verifier; the native authoring record is reused while its inputs remain fresh.

An initial authoring-runner defect launched its own apphost recursively. Pingu
intervened, remaining task processes were stopped and both old apphosts disabled;
zero remaining processes was verified. The fixed runner has UseAppHost=false,
rejects all arguments before launching a child, derives and validates the absolute
dotnet host, and makes at most two sequential FSI calls with timeout/tree cleanup.
The argument rejection was executed before subsequent real FSI checks. The faulty
run is not evidence for FSI semantics. Process/user/machine PATH stayed unchanged.

## Inspect what an agent receives

Adapted from [the MCP Inspector walkthrough](../inspect-guidance.md). This block
is tested from C:\Windows before selecting the literal task worktree. Setup needs
Node 22.19+ and network access for pinned Inspector; the server serves embedded
guidance offline. Every call initializes and closes the real built server.

```powershell
& {
  Set-Location -LiteralPath 'V:\_worktrees\Playbook\t3-d1f12b9c'
  $ErrorActionPreference = 'Stop'
  $PSNativeCommandUseErrorActionPreference = $true
  $env:DOTNET_ADD_GLOBAL_TOOLS_TO_PATH = '0'
  $dotnet = 'C:\Program Files\dotnet\dotnet.exe'
  $node = 'C:\Program Files\nodejs\node.exe'
  & $dotnet build ./src/PinguApps.Playbook -c Release
  & $node 'C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js' install --prefix ./artifacts/inspector --ignore-scripts --no-audit --no-fund @modelcontextprotocol/inspector@2.11.0
  $inspector = (Resolve-Path ./artifacts/inspector/node_modules/@modelcontextprotocol/inspector/clients/launcher/build/index.js).Path
  $server = (Resolve-Path ./src/PinguApps.Playbook/bin/Release/net10.0/PinguApps.Playbook.dll).Path
  $list = & $node $inspector --cli --format json --quiet --method tools/call --tool-name list_recipes --tool-arg 'targetVersion="11.0"' --tool-arg query=fsharp-lifetimes -- $dotnet $server mcp | ConvertFrom-Json
  $list.result.structuredContent.recipes | Format-List id, title, goal, stability
  foreach ($entry in $list.result.structuredContent.recipes) {
    $detail = & $node $inspector --cli --format json --quiet --method tools/call --tool-name get_recipe --tool-arg 'targetVersion="11.0"' --tool-arg "id=$($entry.id)" -- $dotnet $server mcp | ConvertFrom-Json
    $recipe = $detail.result.structuredContent.recipe
    $recipe | Format-List id, edition, stability
    $recipe.markdown
    $recipe.applicability.routes | ConvertTo-Json -Depth 15
  }
}
```

Expect three reusable ID/title/goal summaries, one explicitly experimental
sequence recipe and two ordinary stable-language recipes. Full detail contains
the original comparisons/support, target-11 applicability, RC2 limits and current
compilation evidence. Missing bodies, unresolved snippet tokens, a preview
requirement on ordinary FSI use or a supported target-10 runtime-async route fail
inspection. This server check is distinct from the installed-package harness.
