## Acceptance-criteria coverage

All three targets' criteria 1–5 map to four original goal-based editions 11.0,
canonical actual .NET 10/11 sample projects, complete metadata/Markdown and
official sources, current input-hashed evidence, the existing real installed
stdio harness, and updated source dispositions. These are .NET 11 editions;
.NET 10 comparisons do not add to the eight approved historical foundations.
No older-target route or experimental opt-in is invented.

- **PIN-742 criteria 6–7:** `reflection.inspect-loaded-metadata` checks ownership,
  metadata-only nullable Int32, constructor arity, a direct custom Type's inherited
  default failure on .NET 11 and its explicit non-nullable override. TypeDelegator
  is not substituted for that regression. `hosting.report-assembly-location`
  checks a stream-loaded module, a logical label, preservation of unrelated
  locations and rejection of a second registration. Separate deployment records
  assert caller outcomes and unavailable/physical locations across both releases.
- **PIN-743 criteria 6–7:** `tooling.annotate-code-strings` compiles C#/F#/Visual
  Basic annotations, inspects their exact emitted identifiers and passes invalid
  source through unchanged. No editor highlighting/completion or runtime parser
  is claimed.
- **PIN-744 criteria 6–7:** `uri.identify-data-uris` uses UriSchemeData and all five
  Video media constants. It classifies data/HTTPS, rejects relative/unknown-format
  input and recognises a malformed data payload without claiming to validate it.
  Provisional uri.handle-schemes, mime.describe-content and mime.describe-video-content
  are consolidated into this single concrete ID.

The installed test compares complete rendered bodies with embedded canonical
sources, structured/text equality, discovery goals, edition 11.0 and applicability,
fresh evidence and explicit target-10 rejection. It adds one focused scenario to
the existing harness, not another OS/client/native matrix.

## Inspect what an agent receives

Adapted from [the MCP Inspector walkthrough](../inspect-guidance.md).
PowerShell 7.3+, SDK 10.0.402 and Node 22.19+ are needed. Setup installs pinned
Inspector 2.11.0 locally with lifecycle scripts disabled; no global tool or PATH
change is needed. Playbook serves embedded content without fetching guidance.

```powershell
& {
  $ErrorActionPreference = 'Stop'
  $PSNativeCommandUseErrorActionPreference = $true
  Set-Location -LiteralPath 'V:\_worktrees\Playbook\t3-fe584233'
  $env:DOTNET_ADD_GLOBAL_TOOLS_TO_PATH = '0'
  $dotnet = 'C:\Program Files\dotnet\dotnet.exe'
  & $dotnet build ./src/PinguApps.Playbook -c Release
  & 'C:\Program Files\nodejs\npm.cmd' install --prefix ./artifacts/inspector-2.11.0 --ignore-scripts --no-audit --no-fund --package-lock=false @modelcontextprotocol/inspector@2.11.0
  $server = (Resolve-Path ./src/PinguApps.Playbook/bin/Release/net10.0/PinguApps.Playbook.dll).Path
  $inspector = (Resolve-Path ./artifacts/inspector-2.11.0/node_modules/@modelcontextprotocol/inspector/clients/launcher/build/index.js).Path
  $call = { param($tool, $argument)
    & 'C:\Program Files\nodejs\node.exe' $inspector --cli --format json --quiet --method tools/call --tool-name $tool --tool-arg 'targetVersion="11.0"' --tool-arg $argument -- $dotnet $server mcp | ConvertFrom-Json
  }
  foreach ($id in @('reflection.inspect-loaded-metadata','hosting.report-assembly-location','tooling.annotate-code-strings','uri.identify-data-uris')) {
    $list = & $call list_recipes "query=$($id.Split('.')[1])"
    $list.result.structuredContent.recipes | Format-List id, title, goal
    $detail = & $call get_recipe "id=$id"
    $recipe = $detail.result.structuredContent.recipe
    $recipe | Format-List id, edition, introducedIn
    $recipe.markdown | Show-Markdown
    $recipe.applicability.routes | ConvertTo-Json -Depth 15
  }
}
```

Expect four ID/title/goal summaries, full original comparisons, edition/introduction
11.0 and explicit applicability. Missing Markdown, unresolved snippet tokens,
missing constraints or a false editor/payload/native claim are failures. Every
Inspector call starts and closes the actual built server. The block is tested
from an unrelated directory before handoff.
