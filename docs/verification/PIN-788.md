## Criteria and scope

- Original prose and actual .NET 10/11 TideDesk hosts and browser clients solve
  the same harbour-check startup/reconnect goal. JavaScript remains a valid
  .NET 10 approach; no historical C# BrowserOptions API is invented.
- Complete offline Markdown includes both project pairs, exact package/SDK pins,
  namespace/imports, client boot, document, CSS, render modes and startup scripts.
  Snippets come from canonical sources. Runtime/SDK/language, package assets,
  providers, platform/rendering and prerelease limits are explicit.
- Both declared hosts and both actual browser clients compile. Real HTTP and
  Chromium checks establish options generation, precedence, scalar conversions,
  startup and reconnection. Source review and compile evidence are separate.
- Existing real packed-tool tests check the full expanded body, target/edition,
  current evidence and every authored route property with DeepEquals, including
  nested requirements, assets, constraints, providers, sources and evidence paths.
  They retain the single existing web scenario and all sibling recipe assertions.
- The inventory and Blazor source dispositions retain goal/edition identity and
  sibling startup-JS, circuit pause, transport, configuration and culture ownership.
  No tracker write, deployment, merge, release, account or resource provisioning.
- Final RC1 group names are InteractiveServer, StaticServer and
  InteractiveWebAssembly. Static lookup is BrowserOptions.GetBrowserOptions.
- Generated configuration and actual Server/Auto(Server) reconnection are tested.
  Separate-request sharing is measured only on the pinned RC2 composition.
- Server, WebAssembly and cold/warm Auto startup use actual compatible client
  assets. Standalone WASM without a component endpoint is explicitly excluded.

## Inspect what an agent receives

Adapted from [the Inspector walkthrough](../inspect-guidance.md).
Requires PowerShell 7, .NET SDK 10.0.402 and Node 22.19+. Build/Inspector setup is
online; the actual built stdio server returns embedded guidance offline. The
literal worktree block below was tested from C:\Windows. Each Inspector call
initializes, calls the server and shuts it down; no service remains running.

```powershell
Set-Location -LiteralPath 'V:\_worktrees\Playbook\agent-pin-788-04-016-server-configured-blazor-browser-startup'
$ErrorActionPreference = 'Stop'
$PSNativeCommandUseErrorActionPreference = $true
$env:DOTNET_ADD_GLOBAL_TOOLS_TO_PATH = '0'
$dotnet = 'C:\Program Files\dotnet\dotnet.exe'
$node = 'C:\Program Files\nodejs\node.exe'
& $dotnet build ./src/PinguApps.Playbook -c Release
& $node 'C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js' install --prefix ./artifacts/inspector --ignore-scripts --no-audit --no-fund @modelcontextprotocol/inspector@2.11.0
$inspector = (Resolve-Path ./artifacts/inspector/node_modules/@modelcontextprotocol/inspector/clients/launcher/build/index.js).Path
$server = (Resolve-Path ./src/PinguApps.Playbook/bin/Release/net10.0/PinguApps.Playbook.dll).Path
$common = @('--cli', '--format', 'json', '--quiet', '--method', 'tools/call', '--tool-arg', 'targetVersion="11.0"')
$list = & $node $inspector @common --tool-name list_recipes --tool-arg query=tide-policy -- $dotnet $server mcp | ConvertFrom-Json
$list.result.structuredContent.recipes | Format-List id, title, goal
$detail = & $node $inspector @common --tool-name get_recipe --tool-arg id=blazor.configure-browser-from-server -- $dotnet $server mcp | ConvertFrom-Json
$recipe = $detail.result.structuredContent.recipe
if ($recipe.id -cne 'blazor.configure-browser-from-server' -or $recipe.edition -cne '11.0') { throw 'Wrong recipe/edition' }
$recipe.markdown | Write-Output
$recipe.applicability | ConvertTo-Json -Depth 30
$recipe.sources | Format-Table -Wrap
$recipe.evidence | Select-Object sample, target, sdk, kind, freshness | Format-Table
$detail | ConvertTo-Json -Depth 60 | Set-Content ./artifacts/pin788/returned.json
```

Expect exactly the reusable ID `blazor.configure-browser-from-server`, title
**Set browser startup policy from C#**, goal **Manage Blazor startup and
reconnection from C#**, edition 11.0, all four current compile records, full
expanded Markdown and complete applicability. Target 10.0 returns
no_applicable_edition; it is a comparison, not a new BrowserOptions route.
Failure includes a missing body/setup file, stale evidence or wrong target/edition.
