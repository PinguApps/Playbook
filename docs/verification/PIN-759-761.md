## Inspect what an agent receives

The following block is exercised from an unrelated temporary directory. It builds the real server and installs only the pinned Inspector client under ignored artifacts. It prints all eight discovery goals and complete bodies, selected applicability and proof status. These are built-server calls; the automated installed scenario additionally tests the actual package in an isolated feed/cache and unrelated directory, including the network-disabled artifact consumers.

```powershell
Set-Location -LiteralPath 'V:\_worktrees\Playbook\t3-16ef26d1'
$env:DOTNET_ADD_GLOBAL_TOOLS_TO_PATH = '0'
$dotnet = 'C:\Program Files\dotnet\dotnet.exe'
& $dotnet build ./src/PinguApps.Playbook -c Release
& 'C:\Program Files\nodejs\npm.cmd' install --prefix ./artifacts/inspector-2.11.0 --ignore-scripts --no-audit --no-fund --package-lock=false @modelcontextprotocol/inspector@2.11.0
$server = (Resolve-Path ./src/PinguApps.Playbook/bin/Release/net10.0/PinguApps.Playbook.dll).Path
$inspector = (Resolve-Path ./artifacts/inspector-2.11.0/node_modules/@modelcontextprotocol/inspector/clients/launcher/build/index.js).Path
$cli = @('--cli', '--format', 'json', '--quiet')
$target = 'targetVersion="11.0"'
$list = & 'C:\Program Files\nodejs\node.exe' $inspector @cli --method tools/call --tool-name list_recipes --tool-arg $target --tool-arg query=sdk-workflows -- $dotnet $server mcp | ConvertFrom-Json
$list.result.structuredContent.recipes | Format-List id, title, goal
foreach ($summary in $list.result.structuredContent.recipes) {
    $response = & 'C:\Program Files\nodejs\node.exe' $inspector @cli --method tools/call --tool-name get_recipe --tool-arg "id=$($summary.id)" --tool-arg $target -- $dotnet $server mcp | ConvertFrom-Json
    $recipe = $response.result.structuredContent.recipe
    $recipe.markdown | Show-Markdown
    $recipe.applicability.routes | ConvertTo-Json -Depth 15
    $recipe.humanProof | Format-List
}
```

Expect eight reusable ID/title/goal summaries; the foundation is edition 10.0, and the other seven are edition 11.0. Bodies contain original comparisons and no unresolved snippet tokens. The mobile watch recipe must report pending proof and the publication blocker; the other seven have no required Human proof. For target 10 only the foundation and conditional composition route are selected. Inspecting detail is mandatory before applying a discovery result. A missing body/goal/applicability, a silently widened target or lost native warning is a failure.
