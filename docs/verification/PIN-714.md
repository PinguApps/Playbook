# PIN-714: static interface helpers

## Delivered boundary and source reconciliation

Recipe `csharp.static-interface-helpers`, edition/introduction **11.0**, serves original guidance for sharing helpers beside an interface without adding implementation obligations. The planetarium samples generate invariant station labels, preserve validation and leave implementers responsible only for Station. The .NET 10 comparison uses a valid companion utility; the .NET 11 example places public/private non-virtual static methods on the interface.

The inventory headline needed qualification. [Canonical RC1 notes](https://github.com/dotnet/core/blob/ffed591b0fb8f9aab50ecc28f2c765049fb28d8f/release-notes/11.0/preview/rc1/csharp.md) include non-virtual static interface members among stabilized features. [Roslyn 83097](https://github.com/dotnet/roslyn/pull/83097) and [the language-design discussion](https://github.com/dotnet/csharplang/blob/main/meetings/2026/LDM-2026-02-11.md) clarify that the change removes a default-interface-method runtime-support gate. [C# 8's static/private rules](https://github.com/dotnet/csharplang/blob/main/proposals/csharp-8.0/default-interface-methods.md) predate it. The same canonical interface surface is therefore also compiled and executed on .NET 10/C# 14. This does not deliver a ninth .NET 10 foundation. Legacy-runtime behavior remains source-reviewed only; no .NET Framework/netstandard or unsupported language/target route is offered.

Sources used: PIN-714 and its comments; the pinned originating SPEC.md (`0a8989814ea11346354464b845c79c15bb71c5e9`); approved proposal `b3778cc`, key SH_L04; current SPEC.md, glossary, four ADRs, contributing/inspection guidance, coverage and verification plans, inventory and existing sample/packed-consumer harness. Root PLAN.md, CONTEXT.md and CONTEXT-MAP.md are absent. The only related Linear issue affecting delivery was PIN-668: its Done status and completed packed-consumer prerequisite permit reuse. No related Linear issue changed. No explicit ticket source or attachment was unavailable. Historical planning statements describing an unimplemented tool are superseded by the actual repository. The cumulative C# overview omits the helper headline; canonical RC notes and compiler sources resolve it.

## Inspect what an agent receives

Requires PowerShell 7.3+, SDK **10.0.402** and Node **22.19+**. Setup downloads pinned Inspector dependencies into ignored artifacts. The built server serves embedded content without network retrieval. This follows [the MCP Inspector walkthrough](../inspect-guidance.md), using the direct Node launch to avoid the known npm executable-name lookup failure.

```powershell
& {
    $ErrorActionPreference = 'Stop'
    $PSNativeCommandUseErrorActionPreference = $true
    Set-Location V:\_worktrees\Playbook\t3-bb35a1ae
    dotnet build ./src/PinguApps.Playbook -c Release
    npm install --prefix ./artifacts/inspector-2.11.0 --no-audit --no-fund --package-lock=false @modelcontextprotocol/inspector@2.11.0
    $server = (Resolve-Path ./src/PinguApps.Playbook/bin/Release/net10.0/PinguApps.Playbook.dll).Path
    $inspector = (Resolve-Path ./artifacts/inspector-2.11.0/node_modules/@modelcontextprotocol/inspector/clients/launcher/build/index.js).Path
    $cli = @('--cli', '--format', 'json', '--quiet')
    $catalogue = node $inspector @cli --method tools/call --tool-name list_recipes --tool-arg 'targetVersion="11.0"' --tool-arg 'query=static interface helpers' -- dotnet $server mcp | ConvertFrom-Json
    $catalogue.result.structuredContent.recipes | Format-List id, title, goal
    $response = node $inspector @cli --method tools/call --tool-name get_recipe --tool-arg id=csharp.static-interface-helpers --tool-arg 'targetVersion="11.0"' -- dotnet $server mcp | ConvertFrom-Json
    $recipe = $response.result.structuredContent.recipe
    $recipe | Format-List id, edition, introducedIn
    $recipe.markdown | Show-Markdown
    $recipe.applicability.routes | ConvertTo-Json -Depth 15
}
```

Expect one discovery result with the stable ID, title **Share helpers on an interface without adding implementation requirements**, and a goal explaining fixed implementation without implementer duties. Detail must show edition/introduction **11.0**, both complete original implementations/consumers, the historical qualification, migration and access/dispatch constraints. Applicability must show the **11.0** route, SDK **11.0**, language **15.0**, no additional packages/workloads/providers/rendering requirements and the RC2 warning. Missing content, unresolved snippet tokens or absent applicability is a failure. Each Inspector call closes its server automatically.
