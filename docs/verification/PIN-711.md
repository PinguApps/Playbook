## Inspect what an agent receives

Requires PowerShell 7, SDK 10.0.402 and Node 22.19+. The first npx command may download Inspector; the server itself retrieves no content from the network. This builds the real server and calls both tools, following [the Inspector walkthrough](../inspect-guidance.md). It needs no SDK 11 installation to read the saved guidance.

```powershell
Set-Location -LiteralPath (git rev-parse --show-toplevel)
dotnet build ./src/PinguApps.Playbook -c Release
$server = (Resolve-Path ./src/PinguApps.Playbook/bin/Release/net10.0/PinguApps.Playbook.dll).Path
$inspector = @('--yes', '@modelcontextprotocol/inspector@2.11.0', '--cli', '--format', 'json', '--quiet')
npx @inspector --method tools/list -- dotnet $server mcp
$catalogue = npx @inspector --method tools/call --tool-name list_recipes --tool-arg 'targetVersion="11.0"' -- dotnet $server mcp | ConvertFrom-Json
$ids = @('csharp.closed-results', 'csharp.closed-hierarchies', 'json.serialize-closed-results', 'json.infer-closed-polymorphism')
$catalogue.result.structuredContent.recipes | Where-Object id -in $ids | Format-List id, title, goal
foreach ($id in $ids) {
    $response = npx @inspector --method tools/call --tool-name get_recipe --tool-arg "id=$id" --tool-arg 'targetVersion="11.0"' -- dotnet $server mcp | ConvertFrom-Json
    $recipe = $response.result.structuredContent.recipe
    $recipe | Format-List id, edition, introducedIn, title, goal
    $recipe.markdown | Show-Markdown
    $recipe.applicability.routes | ConvertTo-Json -Depth 15
}
```

Expect exactly list_recipes/get_recipe, four selected discovery entries with reusable titles/goals, and complete rendered Markdown for each. Each detail has edition/introduction **11.0**, a **11.0** route, SDK family **11.0**, language **15.0**, and the RC2 limitation. There must be no unresolved snippet tokens. The descriptions cover distinct cases, null/default and compiler/serializer boundaries. Unknown or missing content, an unexpected target, or absent constraints is a failure. Inspector closes each server automatically; no service needs stopping.

The ordinary discovery budget now applies the existing **65,000-byte default-page** limit to a growing catalogue rather than retaining a one-recipe 10,000-byte result limit; every summary still has the existing **3,000-byte** budget. No warning is shortened to fit. Fixture page limits remain unchanged. See [the original measurements](PIN-974.md); this is a deliberate catalogue-growth adjustment, not a response-schema change.
