Important measured distinctions:

- In Create mode ZIP ReadWrite remains write-only. In Update mode Write discards old bytes while ReadWrite retains them. Wrong mode/access pairs throw InvalidOperationException. Missing encrypted-entry passwords throw ArgumentException; wrong passwords fail with InvalidDataException in the checked cases. AES-256 is the example default; legacy ZipCrypto is explicitly weak.
- Stored ZIP payload corruption retains valid structure and recorded CRCs; TAR corruption changes a valid name without recalculating the checksum. .NET 10 accepts those inputs; RC2 rejects them at the documented read boundaries. TAR checksums do not cover arbitrary payload contents; neither checksum authenticates the sender.
- The original GNU sparse 1.0 PAX fixture has a 517-byte stored map/data body but 16 logical bytes in two extents. .NET 10 exposes stored bytes; RC2 reconstructs data and holes. Selecting GNU format is not a sparse writer or proof of physical sparse allocation.
- No-write Deflate/GZip output is 0/0 bytes on .NET 10 and 2/20 bytes on RC2. Those measured lengths are not permanent wire-format size promises. Reusable Deflate/ZLib/GZip/Zstandard encoders and decoders are reset only between completed independent frames.
- All four new projects resolve **zero NuGet dependencies**. Built-in RC2 Zstandard comes from `System.IO.Compression`, not the removed separate preview package. No older package asset or third-party encryption/Zstandard route is advertised. Unsupported older equivalents throw explicitly instead of silently substituting a different format or unprotected archive.

The examples are finite trusted desktop/server payloads, not an unbounded untrusted-archive service. Constraints cover staging, late failures, partial extraction, overwrite, cancellation, passwords, format negotiation, output budgets, window limits and resource disposal. Browser/WASI, particular external archive applications, dictionaries/prefix interoperability, Brotli-specific tuning, hard-link migration (PIN-684), native UI/devices, trimming/AOT and GA reconciliation are not claimed by these bounded examples. The source register preserves adjacent grouped work instead of declaring the whole family complete. RC2 execution is not GA proof; no mocks or cross-compilation substitute for execution.
