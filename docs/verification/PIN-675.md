## Reproduce the agent-visible check

Use the [installation guide's copyable build/pack/install and Inspector commands](../installation.md#build-and-inspect-the-current-development-package). They show both discovery descriptions and full detail through the actual installed server. Expected discovery is `csharp.validate-property-assignment`, **Normalize and validate properties with the C# field keyword**, with its reusable goal. Detail must include offline Markdown, .NET 10 / C# 14 primary requirements and the separately labelled SDK 11 alternative. Coverage remains incomplete.

For a previously restored local manifest, the equivalent launch can be checked with:

```powershell
Set-Location <consumer-repository>
dotnet tool run playbook -- --version
$inspector = @('--yes', '@modelcontextprotocol/inspector@2.11.0', '--cli', '--format', 'json', '--quiet')
$detail = npx @inspector --cwd (Get-Location).Path --method tools/call --tool-name get_recipe --tool-arg id=csharp.validate-property-assignment --tool-arg 'targetVersion="10.0"' -- dotnet tool run playbook -- mcp | ConvertFrom-Json
$detail.result.structuredContent.recipe.markdown
$detail.result.structuredContent.recipe.applicability | ConvertTo-Json -Depth 15
```

With intentionally isolated homes/caches, add `-e "DOTNET_CLI_HOME=$env:DOTNET_CLI_HOME" -e "NUGET_PACKAGES=$env:NUGET_PACKAGES"` to Inspector before `--method`; set those variables only in the test process. Inspector's first download requires network access. Stop a manually started `playbook mcp` with Ctrl+C; these Inspector calls close automatically. Temporary test installs can be removed after inspection; no client settings need reverting.
